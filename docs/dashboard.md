# 看板固件与上位机

## 组成

| 位置 | 作用 |
|---|---|
| 固件分支 `dashboard` | 面向看板的精简固件，可 OTA，体积约 28KB |
| `host/epdash.py` | 差分、窗口、局刷、计时 |
| `dashboard/refresh.py` | 渲染加推屏的一体入口，供计划任务调用 |
| `dashboard/epd_update.py` | 抓数据并用 Edge 无头截图输出 800x480 PNG |

## 固件新增命令

| 命令 | 作用 |
|---|---|
| 0x39 | 触发 DRF，并在设备内部记录真实耗时，回传 `ms=数字` |
| 0x3A | 回传 `ready=0/1`，表示本次上电后面板缓冲是否还有效 |

0x39 的忙等改成先等 BUSY 拉低再等释放。原来的写法在 BUSY 尚未拉低时会立即返回，主机测到的时间不可信。

## 关键结论

### 断线必须保活

`on_disconnect` 原来调用 `drv->sleep`，也就是 POF 加 DSLP。手册写明寄存器数据只能保留到 VDD 断电或进入深睡，所以深睡会清掉 NEW/OLD 缓冲，下次只能全刷。

现在断开时只发 POF，并把 RST 保持高电平。POF 关掉升压但保留 RAM，VDD 一直在。

### 真局刷靠零波形

PSR 置 0x3F，进入黑白模式并从寄存器取波形。CDI 的 0xA9 打开 N2OCP，每次刷新结束把 NEW 拷进 OLD。

四张转移波形里，未变化的像素走 LUTWW 和 LUTKK。把这两张写全零，它们就完全不被驱动，这才是真正的局部刷新。

### PTOUT 必须在 DRF 之后

PTL 设置的窗口只在 PTIN 期间限制扫描。如果在 DRF 之前发 PTOUT，控制器已经退出局部模式，DRF 就会扫描整屏。

早期测试把 PTOUT 发在 DRF 前面，看到完整波形整屏闪，于是误判为窗口限制不了驱动。把 PTOUT 移到 DRF 之后，只刷 60x60 的窗口时，只有那一小块变化，上一轮留在别处的黑色标记原样保留。

正确顺序：

```
PTIN -> PTL 窗口 -> 写数据 -> DRF -> PTOUT
```

### 三色也能窗口刷新

三色模式没有 NEW/OLD，做不到按像素跳过，但窗口仍然限制扫描范围。窗口外的像素不被驱动，红色和黑白都能保持。

实测整屏三色画红矩形，再在另一个位置开窗口刷黑。上一轮留在窗口外的黑色标记没有被重新驱动，证明窗口外确实没有扫描。

### 三色窗口刷新与混合方案

实测确认：

- 三色模式也能窗口刷新，窗口外完全不驱动
- 红色像素在切到黑白模式做局刷后完整保留
- 三色 OTP 波形 17.2 秒，红色正确
- 自写三色寄存器波形 2.6 秒，但红色驱动力不足，只有原本已经浮到表面的红色粒子能显示
- 大块黑转白会留下灰影，完整波形的窗口刷新只能减轻，不能一次清干净

推荐架构：

- 平时用黑白局刷，2.6 秒，红色元素不参与驱动所以保持不变
- 红色内容发生变化时做一次三色整刷，17.2 秒，红色重建
- 三色整刷后 DTM1 里是黑白画面，正好是黑白模式的旧图，可以直接接着局刷
- 每 12 次局刷插一次清场

自写三色波形的红色表还需要调，目标是在 3 到 5 秒内把红色粒子可靠地翻上来。参数在 `host/epdash3.py` 的 `RED` 数组里。

### 快速红色波形的三次尝试

| 做法 | 结果 |
|---|---|
| 把 OTP 原始字节直接写进寄存器 | 刷新卡死，格式不匹配 |
| 用 docs/README.md 里另一块三色屏的 LUT | 34.1 秒，黑白红都出不来，只剩淡影 |
| 简单 VDHR 与 GND 交替，60 帧 | 2.6 秒，只有原本已经浮起的红色粒子显示 |

结论：红色波形和面板的粒子体系强相关，不能跨型号照搬。

要拿到这块屏可用的快速红色波形，只有两条路：

1. 解码本机 OTP。地址是 LUTC 0x0050、LUTR 0x008C、LUTW 0x00C8、LUTK 0x0104，室温约 20 度对应 TR4，起始 0x0425。每张表 60 字节，但字节顺序和寄存器格式不同，直接按 6 字节分组得到的重复次数字段明显不合理，需要进一步比对
2. 上机做参数搜索，以已能出红色的 OTP 波形为基准，逐段削减帧数和重复次数

### 隔夜保活实测

2026-11-02 夜到 11-03 早，实测 12 小时。

做法：三色整刷后，用黑白零波形局刷在左上角画一个 64x64 黑方块，然后断开，只发 POF 并保持 RST 高电平。

第二天重连，用同一窗口擦白。结果：

- 方块从纯黑变成灰色，说明旧图缓冲还在，K 到 W 的转换被执行了
- 只有那个窗口闪，屏幕其他地方完全不动
- 红色元素一点没变淡
- 电压从 2689 mV 降到 2619 mV

结论：面板缓冲可以跨整夜保留，30 分钟一次的更新不用每次重置。

方块没变纯白，说明黑转白的驱动仍然偏弱。要更干净，需要加强 LUTKW 的重复次数，或者接受周期性清场。

### 设备侧可验证

读 FLG 寄存器 0x71，D6 是 PTL_Flag：

| 状态 | FLG | PTL |
|---|---|---|
| 普通模式 | 0x13 | 0 |
| PTIN 之后 | 0x53 | 1 |
| PTOUT 之后 | 0x13 | 0 |

### 帧时间

设备内计时显示整屏完整波形 2662 毫秒，约 124 帧，单帧约 20 毫秒。OTP 默认波形约 780 帧，对应 16.7 秒。

局刷和整屏耗时一样，因为耗时由波形帧数决定，和窗口大小无关。真正省下的是数据传输量和窗口外的闪烁。

### 残影标定

在固定的 200x200 方块里黑白交替局刷 12 次，最后停在白色。人眼几乎看不出色差，凑近才有一点点。所以连续 12 次局刷插一次整屏清场是安全的。

### 红色层

三色模式 PSR 用 0x0F，CDI 用 0x77。DTM1 是黑白层，DTM2 是红色层，数据位 0 表示红。

整屏三色刷新走面板自带 OTP 波形，实测 17.2 秒。

三色模式和黑白模式的缓冲布局不同，来回切换会把对方的图当成本模式的数据解释。所以红色只能整屏刷，不能和黑白局刷混用。

## 用法

```powershell
python dashboard/refresh.py            # 抓数据、渲染、差分推屏
python dashboard/refresh.py --full     # 强制整屏
python host/epdash.py image.png        # 只推一张图
python host/epdash.py image.png --dry-run
```

状态保存在 `host/.epdash_state.npz`，记录上一帧和局刷计数。连续 12 次局刷后自动插一次整屏刷新，清除残影。

## 已知限制

- 三色模式不能按像素跳过，只能按窗口。窗口内所有像素都会被驱动，改一个红点也要整块窗口刷一次，OTP 波形 17.2 秒
- 大块实心填充会出现透底，因为未变化像素不被驱动，残留灰度会显出来。实测文字和数字更新完全看不出残留，三个价格同时改也没有残影
- 完整波形 2.66 秒，还能压到 1 秒左右，代价是驱动更弱、残影更明显
